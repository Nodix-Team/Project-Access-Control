Fondasi dari Sprint 1 & 2

00Prasyarat & Setup

1. Nyalakan MySQL & EMQX, isi backend/.env

docker ps   # pastikan container MySQL & EMQX jalan

Isi backend/.env — nama variabel harus sama persis dengan yang dibaca app/config.py:

# DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME -> sesuai container MySQL kamu
JWT_SECRET_KEY=apapun-yang-penting-tidak-kosong
MQTT_HOST=localhost
MQTT_PORT=1883
MQTT_USERNAME=backend
MQTT_PASSWORD=backend123
AUTH_ENABLED=false

2. Install dependency (sudah termasuk paho-mqtt)

cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

3. Jalankan server, lalu login

uvicorn app.main:app --reload

Terminal baru — simpan token, dipakai semua request /api/* di bawah:

$body = @{ username = "admin"; password = "admin123" } | ConvertTo-Json
$login = Invoke-RestMethod -Uri http://localhost:8000/api/auth/login -Method Post -Body $body -ContentType "application/json"
$headers = @{ Authorization = "Bearer $($login.access_token)" }

4. Jalankan simulator controller (terminal ketiga)

python tools/simulate_esp32.py 127.0.0.1

Simulator mewakili ctrl-A & ctrl-B sekaligus. Perintah yang dipakai berulang di bawah: tap <ctrl-A|ctrl-B> <kartu> <pintu>.

04.1Koneksi MQTT

04.1 — Client hidup, reconnect otomatis▸

Backend tidak boleh jatuh kalau EMQX mati, dan harus reconnect sendiri kalau EMQX hidup lagi.

A. Broker hidup saat startup

Invoke-RestMethod http://localhost:8000/health
Expect

{"status":"ok","mqtt_connected":true}

B. Broker mati → server tetap hidup

Stop container EMQX, lalu restart uvicorn (Ctrl+C, jalankan lagi).

Expect

Server tetap start normal (tidak crash), mqtt_connected: false, endpoint lain (mis. /docs) tetap 200.

C. Broker hidup lagi → reconnect ≤30 detik

Server dari test B tetap jalan. Start ulang EMQX, lalu poll /health tiap beberapa detik.

Expect

mqtt_connected berubah true sendiri dalam ≤30 detik, tanpa restart server.

04.2Subscribe: Log & Status

04.2 — Tap kartu masuk DB, heartbeat → online▸

Prasyarat: 04.1-C lulus, simulator jalan.

A. Kartu dikenal (John Doe, seed Sprint 2)

tap ctrl-A AABBCCDD 1
Invoke-RestMethod -Headers $headers "http://localhost:8000/api/logs?kartu=AABBCCDD"
Expect

Row baru: user_nama: "John Doe", door_nama: "Lobby Utama", result: "GRANTED", device_uptime_ms terisi.

B. Kartu tak dikenal

tap ctrl-A 00000FADE 1
Expect

Row tetap tersimpan (bukan ditolak), user_id: null.

C. Kartu numerik pendek

tap ctrl-A 555 1
Invoke-RestMethod -Headers $headers "http://localhost:8000/api/logs?kartu=0000000555"
Expect

Tersimpan sebagai 0000000555 (10 digit, di-pad otomatis).

D. Heartbeat → is_online

Biarkan simulator jalan (heartbeat tiap 10 detik).

Invoke-RestMethod -Headers $headers http://localhost:8000/api/controllers
Expect

ctrl-A & ctrl-B is_online: true.

Sekarang hentikan simulator (Ctrl+C) dan tunggu ~90 detik (3× heartbeat_s default 30s) sebelum cek ulang.

Perlu sabar

Bukan hang — ini memang didesain toleran 3× interval heartbeat supaya 1 heartbeat telat tidak dianggap offline palsu.

04.3Publisher: CRUD User → Controller

04.3 — REST CRUD user menembus ke controller▸

Prasyarat: 04.2 lulus. Pakai kartu baru (bukan seed) supaya tidak bentrok data John Doe.

A. Create user dept IT (akses ctrl-A + ctrl-B)

$body = @{ kartu="10203040"; nama="Test Sprint3"; department_id=1; is_custom_access=$false } | ConvertTo-Json
$user = Invoke-RestMethod -Uri http://localhost:8000/api/users -Method Post -Headers $headers -Body $body -ContentType "application/json"
$uid = $user.uid
Expect di terminal simulator

ctrl-A: Upsert User: 10203040 -> [1, 2]
ctrl-B: Upsert User: 10203040 -> [2]

Verifikasi kritis

ctrl-B harus dapat 2 (door_number Lab Komputer), bukan 6 (door_id-nya). Ini inti bug P0-1 dari architecture_review.md.

B. Pindah department → cabut akses ctrl-B

Pindahkan ke HRD (dept 2 — cuma Lobby Utama, tidak menyentuh ctrl-B sama sekali):

$body = @{ department_id = 2 } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:8000/api/users/$uid" -Method Put -Headers $headers -Body $body -ContentType "application/json"
Expect di terminal simulator

ctrl-A: Upsert User: 10203040 -> [1]
ctrl-B: Berhasil menghapus user: 10203040

C. Delete user

Invoke-RestMethod -Uri "http://localhost:8000/api/users/$uid" -Method Delete -Headers $headers
Expect

ctrl-A menerima users/delete untuk 10203040 (controller terdampak terakhir).

04.4Sync Atomik

04.4 — Full sync, staging, retry▸

Prasyarat: 04.2 lulus. Controller ID ctrl-A biasanya 1 di data seed segar — cek dulu lewat GET /api/controllers kalau beda.

A. Sync normal

Invoke-RestMethod -Uri http://localhost:8000/api/controllers/1/sync -Method Post -Headers $headers
Expect di terminal simulator

Memulai sinkronisasi atomik... → beberapa Staging User: ... → Sinkronisasi SUKSES. N user disimpan ke RAM.

Cara verifikasi count

Jangan patokan angka tetap — cocokkan jumlah baris Staging User di simulator dengan count di response API. Kalau baru dari seed segar (belum bikin user baru), harusnya 4 (John, Jane, Bob, Charlie — semua yang aksesnya menyentuh ctrl-A).

B. Sync ke controller offline

Hentikan simulator (Ctrl+C) sepenuhnya, lalu ulangi request sync.

Perlu sabar

Bisa sampai ~90 detik (3 percobaan × timeout 30 detik) — bukan hang, itu retry otomatis bekerja.

Expect

Response akhirnya balik dengan "status":"SYNC_FAILED", "last":"TIMEOUT" — bukan menggantung selamanya.

C. Broker mati saat sync

Stop EMQX, lalu request sync lagi.

Expect

503 Broker MQTT offline — langsung, tanpa mencoba publish apa pun.

04.5WebSocket Live Feed

04.5 — Siaran real-time ke banyak klien▸

Prasyarat: 04.2 lulus. Nyalakan ulang EMQX & simulator kalau sempat dimatikan di 04.4.

A. Siapkan klien WebSocket

Pakai wscat kalau ada Node, atau skrip Python singkat ini (2 terminal terpisah, jalankan sama persis di keduanya):

pip install websockets
import asyncio, websockets, json
async def main():
    async with websockets.connect("ws://localhost:8000/ws/live-feed") as ws:
        print("Terhubung, menunggu live feed...")
        async for msg in ws:
            print(json.dumps(json.loads(msg), indent=2))
asyncio.run(main())

B. Tap sekali, cek 2 klien

tap ctrl-A AABBCCDD 1
Expect

Kedua terminal klien menerima JSON identik dalam <1 detik.

C. Kartu tak dikenal

tap ctrl-A 00000FADE 1
Expect

user_nama: null tetap tersiar ke klien.

D. Tutup 1 klien, tap lagi

Ctrl+C di salah satu terminal klien, lalu tap sekali lagi.

Expect

Klien yang tersisa tetap menerima broadcast; terminal uvicorn tidak menampilkan error.

E. Cek format waktu

Expect

server_ts berakhiran Z murni, contoh 2026-07-16T05:32:36.109447Z — bukan ...+00:00Z.

04.6Log REPLAYED + Config Push

04.6 — Buffer offline & config aman▸

Prasyarat: 04.2 lulus. Bagian ini butuh publish manual (bukan lewat simulator, yang tidak mensimulasikan buffer offline) — pakai MQTT Explorer, atau skrip Python singkat di bawah (device ini sudah punya paho-mqtt terpasang).

A. Publish log REPLAYED manual

import paho.mqtt.client as mqtt
c = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
c.username_pw_set("ctrl-A", "ctrlA123")
c.connect("127.0.0.1", 1883, 60)
c.publish("access/ctrl-A/logs", "AABBCCDD,1,GRANTED,OK,123456,REPLAYED", qos=1)
c.disconnect()
Invoke-RestMethod -Headers $headers "http://localhost:8000/api/logs?is_replayed=true"
Expect

Row baru muncul dengan is_replayed: true.

B. Log biasa (tanpa REPLAYED)

tap ctrl-A AABBCCDD 1
Expect

GET /api/logs?is_replayed=false menyertakan row ini.

C. server_ts tersebar (bukan menumpuk)

Kirim 2–3 publish manual dengan uptime_ms yang jauh berbeda (mis. 1000 lalu 500000), setelah simulator sempat kirim minimal 1 status heartbeat untuk device itu.

Expect

server_ts antar log berbeda signifikan — bukan beberapa log di detik yang sama persis.

Keterbatasan diketahui

Kalau backend belum pernah terima status dari device itu sejak dia hidup, fallback ke NOW() diterima — dicatat eksplisit di CHANGELOG.md, bukan bug.

D. Config push — key aman

$body = @{ heartbeat_s = 60 } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8000/api/controllers/1/config -Method Put -Headers $headers -Body $body -ContentType "application/json"
Expect di terminal simulator

Menerapkan konfigurasi secara lokal: heartbeat_s=60

E. Config push — key berbahaya (wifi/mqtt)

$body = @{ wifi_ssid = "TEST_WIFI" } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8000/api/controllers/1/config -Method Put -Headers $headers -Body $body -ContentType "application/json"
Expect

Tersimpan di DB (cek lewat GET .../config), tidak ada output apa pun di terminal simulator.

Kalau ada langkah yang hasilnya tidak sesuai, salin pesan error / output simulator apa adanya — jangan diringkas — supaya lebih mudah dilacak baliknya.
