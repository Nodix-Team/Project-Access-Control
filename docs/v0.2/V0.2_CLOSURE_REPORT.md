## Temuan Tambahan (di luar checklist roadmap v0.2 manapun)

Ditemukan lewat audit kode langsung (bukan asumsi), belum pernah jadi bagian scope v0.2 karena memang tidak diminta — dicatat di sini supaya tidak hilang, semua sudah masuk scope [`ROADMAP_v0.3.md`](../ROADMAP_v0.3.md):

**Keamanan:**
- Tidak ada HTTPS/TLS di backend maupun MQTT (semua plaintext)
- Tidak ada rate limiting, account lockout, atau MFA di login
- Hanya ada 1 role (`admin`) — tidak ada RBAC
- `JWT_SECRET_KEY` tidak divalidasi saat startup — bisa ke-deploy dengan secret kosong
- MQTT tidak punya ACL per-topic yang sebenarnya, tidak ada LWT
- Kredensial WiFi/MQTT tersimpan **plaintext** di `config.json` firmware, tanpa flash encryption

**Testing &amp; CI/CD:**
- Tidak ada CI/CD (`​.github/workflows` tidak ada sama sekali)
- Backend "test" bukan pytest — script manual ke DB nyata
- Frontend nol test, bahkan belum ada test runner terpasang
- Firmware nol test, tidak ada environment native/Unity

**Firmware/Hardware:**
- Tidak ada driver RFID fisik sama sekali (100% simulasi Serial)
- Tidak ada kontrol relay/aktuator pintu sama sekali
- Tidak ada OTA update
- Tidak ada watchdog/brownout protection
- Pemakaian `String` Arduino berat (~116 kali) — risiko fragmentasi heap jangka panjang
- Tidak ada RTC/NTP — timestamp offline cuma estimasi `uptime_ms`
- **`DEVICE_ID` default firmware (`esp32-ac-001`) tidak cocok dengan controller manapun di seed data** — ditemukan &amp; sempat diperbaiki (jadi `ctrl-B`) saat pengujian dengan ESP32 fisik di sesi ini, tapi perbaikannya di-rollback atas permintaan eksplisit (belum mau di-PR dulu, testing lokal jalan dulu) — **masih jadi item terbuka**, lihat roadmap v0.3

**Database &amp; Operasional:**
- Tidak ada tool migrasi (Alembic) — skema hanya lewat SQL manual
- Tidak ada strategi backup/restore sama sekali
- Tidak ada Dockerfile untuk aplikasi backend sendiri (cuma image pihak ketiga untuk MySQL/EMQX)
- Tidak ada monitoring/alerting/log terpusat

**Produk fisik (di luar cakupan kode, relevan kalau project ini benar-benar jadi produk):**
- Fail-safe vs fail-secure (perilaku kunci saat listrik padam) belum pernah didefinisikan — pertanyaan desain paling fundamental di access control fisik, belum terjawab karena kontrol relay memang belum ada
- Tidak ada desain enclosure, sertifikasi (FCC/CE/RoHS), PoE/battery backup, BOM/PCB

## Tindakan Penutupan yang Disarankan (sebelum v0.3 dimulai)

Supaya v0.2 benar-benar tertutup rapi sesuai definisi roadmap sendiri, urutan yang disarankan:

1. **Perbaiki baris backend di `README.md`** (masih salah tertulis "🔲 Belum")
2. **Centang ulang checklist Sprint 3, 5, 6 di `ROADMAP_v0.2.md`** yang sebenarnya sudah selesai tapi belum tercentang (kerapian arsip)
3. **Tambah heading `## [v0.2.0] - 2026-07-21` di `CHANGELOG.md`**, pindahkan seluruh isi `## [Unreleased]` yang relevan ke bawahnya (mengikuti format Keep a Changelog yang sudah dipakai)
4. **Merge `dev` → `main`**
5. **Tag `v0.2.0`**: `git tag -a v0.2.0 -m "Release v0.2.0"` lalu `git push origin main && git push origin v0.2.0`

Ini murni langkah administratif — tidak ada kode yang perlu ditulis. Beri tahu saya kalau mau saya eksekusi langkah 1–5 ini sekarang, atau nanti setelah `ROADMAP_v0.3.md` juga disepakati.
